# Versions are pinned exactly, not ranged. These libraries are not merely build
# inputs: the committed corpora under tests/oracles/ ARE their output, and CI
# regenerates and diffs them on every pull request. Under a range, a silent
# minor release would land as an unexplained oracle diff on an unrelated change.
# Bump deliberately, and regenerate the corpora in the same commit.
#

# tokenizer.json generators read, and that fetch_xlmr_vocab.py writes the XLM-R

# mapie -- the reference for Lodestar.Conformal's split-conformal corpus (#441).

# doublemetaphone -- the reference for Lodestar.Text's Double Metaphone (#177).
# jellyfish, which oracles the other three phonetic encoders, exports no Double
# Metaphone at all in 1.2.1, so this is a second phonetics oracle rather than a
# reach for a function the existing one already has. Artistic 2.0, read from the
# LICENSE in its own wheel and not from the PyPI classifier: free, GPL-compatible
# and non-copyleft, so ADR 0003's hygiene rule -- the one that excludes abydos
# here, and removed python-Levenshtein earlier -- does not reach it.
# Decision 0075 has the 401-word comparison that chose it over metaphone 0.6 and
# phonetics 1.0.5, and why the field narrowed to one.
doublemetaphone==1.2

# snowballstemmer -- the reference for Lodestar.Text's Hungarian stemmer (#310).
# nltk oracles the other Snowball languages and cannot oracle this one: its
# Hungarian omits 'ő' and 'ű' from the vowel set and 'től', 'ről', 'ből' from
# step 2, so it leaves "nők", "szőlők", "gyűrűk" and every -ből form unstemmed.
# This is the Snowball project's own generated Python package, so the corpus
# freezes the published algorithm rather than one library's transcription of it.
# BSD-3-Clause, no dependencies of its own. Decision 0090 has the measurement.
snowballstemmer==3.1.1

# pyyaml -- tools/tests/test_bench_nightly_permissions.py parses a workflow file to

# colorama — click's Windows-only conditional dependency (click is nltk's;
# click declares it as `colorama; platform_system == "Windows"`). Resolved on
# Linux, that marker is false, so pip-compile never pins it and --require-hashes
# then refuses the whole install on Windows, where click actually needs it.
#
# pip-tools 7.6.1 (the newest release; checked with `pip index versions
# pip-tools`) has no --universal flag, and re-adding the marker here does not
# help either: pip-compile evaluates markers against the resolving host, so a
# conditional entry is dropped exactly like click's is. The only way this
# tool-chain can pin it at all is unconditionally — safe here, since colorama
# is a standalone leaf package (no further dependencies) that click only
# imports and calls on Windows; installing it on Linux is inert.
colorama==0.4.6
