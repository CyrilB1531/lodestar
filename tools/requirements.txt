# Versions are pinned exactly, not ranged. These libraries are not merely build
# inputs: the committed corpora under tests/oracles/ ARE their output, and CI
# regenerates and diffs them on every pull request. Under a range, a silent
# minor release would land as an unexplained oracle diff on an unrelated change.
# Bump deliberately, and regenerate the corpora in the same commit.
#
# Install with --only-binary :all: so that no source distribution runs setup.py.

# mapie -- the reference for Lodestar.Conformal's split-conformal corpus (#441).

# doublemetaphone -- the reference for Lodestar.Text's Double Metaphone (#177).
# jellyfish, which oracles the other three phonetic encoders, exports no Double
# Metaphone at all in 1.2.1, so this is a second phonetics oracle rather than a
# reach for a function the existing one already has. Artistic 2.0, read from the
# LICENSE in its own wheel and not from the PyPI classifier: free, GPL-compatible
# and non-copyleft, so ADR 0003's hygiene rule -- the one that excludes abydos
# here, and removed python-Levenshtein earlier -- does not reach it.
# Decision 0075 has the 401-word comparison that chose it over metaphone 0.6 and
# phonetics 1.0.5, and why the field narrowed to one.
doublemetaphone==1.2

# snowballstemmer -- the reference for Lodestar.Text's Hungarian stemmer (#310).
# nltk oracles the other Snowball languages and cannot oracle this one: its
# Hungarian omits 'ő' and 'ű' from the vowel set and 'től', 'ről', 'ből' from
# step 2, so it leaves "nők", "szőlők", "gyűrűk" and every -ből form unstemmed.
# This is the Snowball project's own generated Python package, so the corpus
# freezes the published algorithm rather than one library's transcription of it.
# BSD-3-Clause, no dependencies of its own. Decision 0090 has the measurement.
snowballstemmer==3.1.1

# statsmodels -- the reference for Lodestar.Stats.Regression's OLS table (#566).
# BSD-3-Clause, on the same footing as scikit-learn and (since decision 0082) scipy.
# sm.OLS(y, X).fit() publishes .bse, .tvalues, .pvalues, .conf_int(), .rsquared_adj,
# .fvalue and .f_pvalue, and statsmodels.stats.outliers_influence the VIF -- the whole
# table from one call. sklearn.linear_model.LinearRegression, already pinned, computes
# no standard error at all, so it can cross-check the coefficients and oracle nothing else.
#
# This is the largest single addition this file has taken: numpy, scipy and packaging
# were already resolved, but pandas, patsy and formulaic arrive with it, and pandas
# brings its own date leaves. It does not qualify for requirements-nodeps.txt --
# decision 0078's test admits a package only when everything it imports is already on
# the lock's graph, and pandas is not. The cost is shared rather than paid twice:
# lifelines, the reference the survival lot (#569) will need, depends on pandas and
# formulaic as well.
statsmodels==0.15.0

# lifelines -- the reference for Lodestar.Survival's Kaplan-Meier, Nelson-Aalen and
# log-rank (#569). MIT, read from the wheel rather than the PyPI classifier. Its own
# Python floor is 3.11, below the 3.12 ADR 0065 sets, so it does not raise ours.
#
# scikit-survival is deliberately absent: its licence is GPL-3.0-or-later, which ADR 0003
# refuses outright. Decision 0098 records that so the question is not reopened.
lifelines==0.30.3
# autograd-gamma is lifelines' own dependency, pinned here rather than left to the
# resolver: pip-compile selects 0.5.0, which publishes no wheel, and every install site
# passes --only-binary :all:. 0.4.2 is the newest that does, and the lock's graph is
# otherwise unchanged by the pin.
autograd-gamma==0.4.2

# rank_bm25 -- the reference for Lodestar.Text.Search's BM25 (#573). Apache-2.0, read
# from the wheel; #573 named it MIT, which the METADATA does not say. Permissive either
# way, so ADR 0003 allows it. Frozen since 2022 and four releases old, which is what a
# behaviour reference wants. bm25s was the other candidate and is not pinned: one oracle
# per algorithm, and this is the better-known dialect of the two.
rank_bm25==0.2.2

# colorama — click's Windows-only conditional dependency (click is nltk's;
# click declares it as `colorama; platform_system == "Windows"`). Resolved on
# Linux, that marker is false, so pip-compile never pins it and --require-hashes
# then refuses the whole install on Windows, where click actually needs it.
#
# pip-tools 7.6.1 (the newest release; checked with `pip index versions
# pip-tools`) has no --universal flag, and re-adding the marker here does not
# help either: pip-compile evaluates markers against the resolving host, so a
# conditional entry is dropped exactly like click's is. The only way this
# tool-chain can pin it at all is unconditionally — safe here, since colorama
# is a standalone leaf package (no further dependencies) that click only
# imports and calls on Windows; installing it on Linux is inert.
colorama==0.4.6

# tzdata — the same bug as colorama above, one package further down: pandas
# (statsmodels') declares `tzdata; sys_platform == "win32"`, so pip-compile on
# Linux evaluates that marker false, never pins it, and --require-hashes then
# refuses the whole install on Windows. Measured, not predicted: the Windows job
# of #588 failed with "In --require-hashes mode, all requirements must have
# their versions pinned with ==" naming tzdata, on a branch whose Linux jobs
# were all green.
#
# Pinned unconditionally for colorama's reason, which holds identically here:
# tzdata is a standalone leaf (PyPI metadata lists no dependencies at all) and
# on Linux pandas reads the system zoneinfo instead, so the wheel is inert.
tzdata==2026.3

# datasketch -- the reference for MinHash and its banded LSH index (#602). MIT, read
# from the wheel's METADATA rather than from PyPI's field, which decision 0075 found
# unreliable. Its permutation coefficients are frozen into the corpus rather than
# reproduced from numpy's generator, so nothing here depends on that stream.
datasketch==2.0.0
# simhash -- the reference for the 64-bit fingerprint (#602). MIT, read the same way.
simhash==2.1.2
