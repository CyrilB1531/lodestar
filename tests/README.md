# Tests

Two test projects per package, both xUnit v3 on Microsoft.Testing.Platform:

- **`<Package>.Tests`**, the suite, targeting `net10.0` and referencing the library's `net10.0`
  build;
- **`<Package>.NetStandard.Tests`**, its mirror, which compiles the *same* test sources (linked,
  not copied) against the library's `netstandard2.0` build (`netstandard2.1` for `Lodestar.Gpu`),
  pinned with `SetTargetFramework` on each `ProjectReference`.

So `dotnet test Lodestar.slnx -c Release` runs everything twice, and must report **36 assemblies**:
without the mirrors, the assemblies shipped to .NET Framework, Mono and Unity would be compiled
and never executed. A new test file is picked up by both. Each mirror carries a
`NetStandardAssemblyGuardTests` class, one fact per assembly it must prove it loaded as
`netstandard`, so a mirror reports more tests than its suite; `tools/check_netstandard_guards.py`
asserts that every Lodestar dependency a mirror loads is pinned.

## Oracles

`oracles/*.json` are reference values frozen from the canonical Python library for each
algorithm, generated by `tools/generate_oracles.py` and replayed by the suites at `1e-9` for
floats and exactly for everything else. Python is a development dependency only.
[`CONTRIBUTING.md`](../CONTRIBUTING.md#oracle-validation) has how to regenerate them.

## Run

```bash
dotnet test Lodestar.slnx -c Release
dotnet test tests/Lodestar.Text.Tests -c Release --filter "FullyQualifiedName~Levenshtein"
```

Read the test count, not the colour: a filter matching nothing exits 8 under `dotnet test`.
