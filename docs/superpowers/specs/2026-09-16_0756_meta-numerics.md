# 0756 — Measuring Meta.Numerics against `Lodestar.Stats` and `PrincipalComponentVariance`

**Status:** written before the work, 2026-09-16.

Issue: [#756](https://github.com/CyrilB1531/lodestar/issues/756).

Reading: [decision 0129](https://github.com/CyrilB1531/lodestar/blob/53af23c2/docs/decisions/0129-four-numerics-libraries-read-and-three-absences-withdrawn.md),
which read `Meta.Numerics` 4.2.0 under the [0074](https://github.com/CyrilB1531/lodestar/blob/53af23c2/docs/decisions/0074-the-phase-2-gaps-restated-on-what-the-packages-export.md)
protocol and found it reports two numbers this repository had described as unavailable below `net8.0`. Re-read here
against the assembly, not the record: 177 exported types, and all nine members the issue names are present.

## Problem

`Lodestar.Stats`' only measured incumbent is `Accord.Statistics` 3.8.0, which is **archived and LGPL-2.1**, and it
covers three families. `PrincipalComponentVariance`'s only incumbent is **NumFlat**, which ships `net8.0` only — so
`docs/guides/performance.md` says the comparison below `net8.0` "has no second row".

`Meta.Numerics` 4.2.0 is **MS-PL**, ships `lib/netstandard2.0`, and was published 2025-07-14. It is not a trial
licence and not archived, so it can be timed. It is the second row, and for five of the eight test families it is the
*first* .NET row this repository has ever had.

## What is measured, read from the assembly

`Meta.Numerics.Statistics`, signatures taken by reflection rather than from the documentation:

| this package | Meta.Numerics 4.2.0 |
| --- | --- |
| `TTest.Independent(a, b, variance: Variance.Pooled)` | `Univariate.StudentTTest(IReadOnlyCollection<double> a, b)` |
| `MannWhitney.Test(a, b)` | `Univariate.MannWhitneyTest(IReadOnlyList<double> a, b)` |
| `KruskalWallis.Test(groups)` | `Univariate.KruskalWallisTest(IReadOnlyList<double>[] samples)` |
| `KolmogorovSmirnov.TwoSample(a, b)` | `Univariate.KolmogorovSmirnovTest(IReadOnlyList<double> a, b)` |
| `OneWayAnova.Test(groups)` | `Univariate.OneWayAnovaTest(IReadOnlyCollection<double>[])`, `.Result` |
| `Wilcoxon.Paired(x, y)` | `Bivariate.WilcoxonSignedRankTest(IReadOnlyList<double> x, y)` |
| `FisherExact.Test(table)` | `new ContingencyTable(int[,]).Binary.FisherExactTest()` |
| `ChiSquare.Contingency(table)` | `new ContingencyTable(int[,]).PearsonChiSquaredTest()` |
| `PrincipalComponentVariance.Compute(matrix, rows, columns)` | `Multivariate.PrincipalComponentAnalysis(columns).Components[i].VarianceFraction` |

A `TestResult` there carries `Statistic.Value` and `Probability`, which are this package's statistic and p-value.

**The pairing that is not obvious, and would otherwise time two different statistics under one name:**
`Univariate.StudentTTest(a, b)` is the **pooled-variance** two-sample t, where `TTest.Independent`'s default is
**Welch**. The benchmark passes `Variance.Pooled` so both sides compute the same thing — the same care
`StatsBenchmarks` already takes with Accord's Yates correction.

## What "agreement" means here, and what is expected not to agree

Both sides are run once outside the timed region and compared before anything is timed
(`bench/README.md` §15). Where they disagree, the number is **recorded in the write-up rather than dropped**, which
is the issue's own acceptance criterion. Three places are expected to disagree, and each is a fact about the
libraries rather than a defect:

1. **Continuity corrections.** `MannWhitney.Test` follows scipy and `ChiSquare.Contingency` applies Yates by
   default; a library that does not apply the same correction produces a different p-value from the same statistic.
   The statistic is compared first, and the p-value second, so the write-up can say which of the two moved.
2. **Exact against asymptotic.** `KolmogorovSmirnov.TwoSample` uses `ExactMethod.Auto` and `FisherExact.Test` is
   exact; where Meta.Numerics takes an asymptotic branch at the same size, the p-values differ by more than
   rounding and the write-up names the branch.
3. **Ties.** The rank tests differ in how they correct for ties. The corpus is drawn from a continuous generator, so
   ties are absent by construction — stated so that a later reader does not read "agrees" as a claim about tied data.

Agreement is asserted at `1e-9` relative where the two compute the same quantity, and the constant that fails a
comparison is reported in `bench/README.md` rather than hidden behind a looser tolerance.

## Placement

- **`MetaNumericsStatsBenchmarks`** in `bench/Lodestar.Stats.Benchmarks`, beside `StatsBenchmarks`: the eight
  families at 100 and 10,000 samples, the shapes `StatsBenchmarks` already uses so the Accord rows and these can be
  read side by side. The package reference moves into that project; it is already referenced by
  `bench/Lodestar.Text.Benchmarks` for the k-means row.
- **`PrincipalComponentVarianceIncumbentBenchmarks`** in `bench/Lodestar.Text.Benchmarks`, beside the NumFlat row,
  so one class holds every incumbent for that member.
- **No `src/` change.** This is a measurement, so nothing ships and there is no version bump, no reference page and
  no equivalence row — `docs/guides/performance.md`, `bench/README.md`, `bench/bench-map.json` and the `README.md`
  incumbent rows are the deliverable.

## Evidence

- **Agreement checked in `GlobalSetup`**, which refuses to time a pair that disagrees past the tolerance, the way
  `KMeansFitIncumbentBenchmarks` refuses to time centres that do not match.
- **Numbers on the named machine** (AMD Ryzen 7 8700G, Ubuntu 26.04.1, .NET 10.0.12), default job, in
  `docs/guides/performance.md`.
- **`README.md`'s `Lodestar.Stats` and `Lodestar.Decomposition` incumbent rows** read from that table rather than
  from the nightly pages.
