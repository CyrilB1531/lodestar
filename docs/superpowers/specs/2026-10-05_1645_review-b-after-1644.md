**Status:** written with the work, 2026-10-05.
**Date:** 2026-10-05.

## The problem

The Review B after #1644, on `main` at `6bf7129f`, measured main against the latest release —
Lodestar.Text 0.7.0 and Lodestar.Embeddings 0.8.0, "the release" below — across sizes, read sizes
and the entry points of a fit, and read the persistence code end to end:

- a token pattern that goes through the Python translation (#1239) fitted five to eight times
  slower than the release, and one long match passed the regex timeout the release finished
  within (#1645);
- a string past the JSON writer's ceiling was refused with `InvalidOperationException` where the
  releases raised the writer's `ArgumentException` (#1646);
- a null vocabulary term or stop word made a save throw `NullReferenceException` where 0.7.0 wrote
  it (#1647);
- a save wrote the caller's stop-word collection as it stood at the save, not the copy the analyzer
  filtered with, since 0.7.0 (#1648);
- small asynchronous saves and a 1.4 MB seekable load cost more than the release (#1649).

## Decisions

- **A text without surrogates takes a plain spelling of the pattern.** On such a text every branch
  the translation adds for pairs — a pair, a guard against starting inside one — matches nothing, so
  dropping them changes no match; a text holding a surrogate, found with one vectorised search,
  keeps the pair-aware spelling, compiled the first time one arrives. A pattern with no capturing
  group is scanned with `EnumerateMatches`, as 0.7.0 scanned it: one `Match` a token was most of
  what remained. `\s` and `\S` outside brackets are spelled as the ranges they cover, which .NET
  searches vectorised, where `[^\s\x1C-\x1F]` kept `\S+` half again slower than 0.7.0's (#1645).
- **A class is read item by item as Python's `re` reads one, and refused where Python refuses it.**
  Each item is a class escape or one code point — `\xHH`, `\uHHHH`, `\UHHHHHHHH`, octal, `\a`…`\v`,
  a surrogate pair — and a range is two code points around a `-`, a hyphen first, last, after a
  range or escaped being a literal. Every literal and range is written as `\uXXXX` escapes, so .NET
  finds no range or class subtraction Python never made: `[a-z-[aeiou]]` is a class and a literal
  `]`, `[\--/]` the range `-` to `/`. `\w`, `\d`, `\s` are widened to Python's sets and `\W`, `\D`,
  `\S` spelled as their complements, BMP ranges, supplementary pairs and lone surrogates, where
  .NET's own read marks, U+203F and U+001C otherwise. The pattern as written is checked by .NET
  first, as 0.7.0 compiled it, a leading `(?u)` aside: one .NET refuses goes out with 0.7.0's
  exception and message, whether or not Python reads it, `[\---\w]` and `[\_]` among them. A class
  Python refuses — a range touching a class escape such as `[\w-.]`, a reversed range, an unknown
  escape — is refused by the translation, and the token pattern reads the pattern as 0.7.0 did, by
  .NET as written. Both spellings are parsed at construction, so none fails at the first text
  holding an emoji. Where the translation still reads otherwise than Python — surrogate units in a
  class, supplementary ranges, constructs Python refuses outside a class — it does as `main` did,
  and #1650 holds it. Review A found the item-by-item rewrites before this one wrong in four ways —
  reversed ranges, accepted ranges, hyphens after a range, subtraction read as .NET reads it — which
  is why the class is now parsed. A differential run against Python 3.12's `re`, 43 patterns over
  2,460 random texts with marks, U+203F, U+001C, astral letters, emoji and lone surrogates, gives
  the same tokens in every case but `[\---\w]`, refused as 0.7.0 refused it; the suite holds the
  readings in five tests, mutation-checked (#1645).
- **The pattern as written is checked whatever the analyzer, and where 0.7.0 checked it**, right
  after the n-gram range and ahead of the analyzer check #1198 added: `char` and `char_wb` refuse
  one .NET refuses, and a null pattern raises `Regex`'s `ArgumentNullException`, its parameter
  named `pattern`, in the vectorizers, `Rake` and `TextRank` alike, where `main` raised an
  `ArgumentException` of its own or a `NullReferenceException` (#1645).
- **The tokens are kept only for n-grams.** Every document's token list was built whether or not an
  n-gram pass would read it, 8 MB on 0.7.0's 9.5 for a fit of 500,000 tokens; `ngram_range=(0, 0)`
  reads it too, which the scikit-learn oracle caught in a first version (#1645).
- **The writer's own exception goes out, before the first byte.** `EnsureWritableText` no longer
  wraps what the trial write raises, Cyril's call: `ArgumentException`, "The JSON value of length
  166666667 is too large and not supported.", as the releases raised it, or `IndexOutOfRangeException`
  for a string whose escaped form passes the writer's buffer, documented beside it; the refusal stays
  before the first byte, in #1618's order (#1646).
- **A null term or stop word is written as JSON `null`**, as 0.7.0 wrote it (#1647).
- **A save writes the stop words as the caller gave them when the vectorizer was built**, a copy
  the analyzer keeps beside the set it filters with, so duplicates are written as 0.7.0 wrote them;
  `Options` still hands back the caller's collection (#1648).
- **A small asynchronous save allocates and waits as 0.7.0's did.** `SpillBuffer` holds its first
  chunk in a field and lists chunks only once there is a second; one chunk is copied out with no
  state machine of its own; the document is written inline rather than through a closure; the idf
  block is flushed ahead only where it is large; an index head that fits one flush is written
  without iterators; the vocabulary read accumulates in locals. The asynchronous save of an index
  of one id stays about 25 ns above 0.8.0's: its head is flushed by awaiting, which is what lets it
  complete on a stream refusing synchronous calls, where 0.8.0 failed (#1640, #1649).
- **Changelog entries** for what #1639 and #1644 changed against the releases (#1646).

## Measured

release from nuget.org and this branch built from the same benchmark source, run alternately, two
or three runs each; each cell gives the runs' means.
