# The Gpu findings of the Review B after #1400

**Issues:** [#1508](https://github.com/CyrilB1531/lodestar/issues/1508) to
[#1520](https://github.com/CyrilB1531/lodestar/issues/1520).
**Status:** written with the work, 2026-09-29.
**Date:** 2026-09-29.

## The problem

The Review B of `Lodestar.Gpu` after #1400, on `main` at `1cf61032`, found thirteen defects.

In the code:

- `GpuContext.Accelerator` handed out a freed accelerator after `Dispose`.
- An OpenCL device type was compared for equality though it is a bitfield.
- Two uploads summed caller sizes in `int`.
- Only the release-on-failure helper was tested, not the four uploads that use it.

In the documentation, the package was described as it stood before #1142 and before its kernels
were measured:

- no Lodestar edge and one target framework;
- a gate defined in a `bench/README.md` section that does not exist;
- a kernel "hardest to clear" that posted the largest gain;
- the wrong section numbers, a buffer count, and a one-kernel NuGet description;
- a citation of a deleted decision.

## Decisions

- **The gate lives in `src/Lodestar.Gpu/performance.md`.** That page now states the gate as the bar
  its tables are read against, and every comment, page, benchmark, test and tool that pointed at a
  `bench/README.md` gate points there.
- **The device type is tested on its bits.** ILGPU's `CLDeviceType` carries no `[Flags]`, so the test
  is on the underlying `cl_device_type` value, which the OpenCL specification defines as a bitfield.
- **The call sites are pinned through their IL.** A device allocation cannot be made to fail in a
  test, so each of the four uploads is checked to call `DeviceOwnership.ReleaseOnFailure`.
