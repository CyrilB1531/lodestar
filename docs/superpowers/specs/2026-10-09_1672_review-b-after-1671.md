**Date:** 2026-10-09.

## The problem

The Review B after #1671, on `main` at `1c86f4a2`, measured main against Lodestar.Text 0.7.0 and
Python 3.12's `re`, "the release" and "Python" below:

- a class or single-item branches joining `\w` with `\S` or `\W`, or naming one set twice, spelled
  the 5,000-unit set of supplementary word characters twice, or beside "any pair": `[\w\S]+\.i` took
  140–190 ms over 300 code points where Python takes 0.08 ms, and `(?i)(\w|\w|\S)+\S\.i` 2.1 s
  (#1672);
- a short text holding a surrogate whose interpreted reading ran past its second was read again
  compiled, but the next one like it paid the second again (#1673);
- on netstandard2.0 the shipped stop-word lists were a `HashSet<string>` a cast could edit for the
  whole process, where net10's frozen set refuses (#1674);
- a pattern repeating an empty-capable item, read by .NET's compiled engine, gave tokens Python does
  not (#1675);
- `.([a-z]){,2}?I|` over `1ai` gave `'a'` where Python gives `''` (#1676);
- `\S+` over many short documents was possibly slower than the release (#1677).

## Decisions

- **A charset is a set.** `SupplementarySet` writes each supplementary set once, drops one another
  holds — Python's decimal digits are word characters, a non-word character is no digit — and
  writes "any pair" for sets that hold every pair between them: `\S`, `\w` with `\W` or `\D`, `\d`
  with `\D`. A negated class whose complement holds every pair keeps its BMP branch alone. Branches
  of one set each are joined at the top of the pattern too, past its global flags, as `sre_parse`
  joins them at any level: `\w|\w` spelled the word pairs twice. Measured
  over a 300-code-point document of cased letters and emoji drawn here, after the first call:
  `[\w\S]+\.i` and `(?i)(\w|\w|\S)+\S\.i` under 1 ms, where Python takes 0.3 and 1.1 ms on the same
  document; the issue's own document gave Python 0.08 and 0.26 ms.
- **The interpreter is rented, not owned.** It reads short texts because compiling the pair-aware
  spelling of `\w` costs 10 ms. Once the interpreter has spent what compiling the pattern's own spelling costs —
  10 ms for `\w`'s 5,000 units, scaled by length, a millisecond at least — counting
  only reads past 0.2 ms, which a short text never takes alone, or has run out once, the pattern
  reads compiled from then on: `(?:(\S)*?\D*?[^ ]+?)+x` read 15 units in 130 ms interpreted against
  6 ms compiled, where Python takes 23 ms. Reads shorter than that are left out, as what threads
  waiting on each other add to many of them is no cost of the interpreter. Time is wall-clock: a read
  a collection or a busy machine slows past 0.2 ms counts too, which at worst compiles the pattern
  once, the 10 ms the interpreter spares, and never changes a token, as only patterns both engines
  read alike switch.
- **A compiled spelling is shared by every reader of its pattern**, thirty spellings, fifteen
  patterns read both ways as `Regex.CacheSize` holds fifteen, the least recently read dropped when
  full, a leading `(?u)` left out of the key. Only a compiled spelling is held, so no reader waits
  on another's compile nor meets its failure; two readers compiling one at once each compile it, and
  one is kept. A pair-aware read stamps its spelling at most once a second, and writes no field the readers share
  otherwise; a plain read stamps nothing, as an atomic count per text made eight threads reading one
  vectorizer 40% slower than `main`, and a clock read per text still 10%: a plain spelling dropped
  costs its next new reader one compile, as each paid in 0.7.0. The advancing
  form an empty-capable pattern tries after an empty match follows its spelling.
  Each new vectorizer of `\w+|.` compiled its own, and 2,000 short documents holding emoji took
  17.6 ms against the release's 4.0; they now take 3.1–3.2 ms. A reader takes the shared spelling as
  soon as another has compiled it, so which engine reads a short text hangs on what the process read
  before. The two engines read apart a repeat of an empty-capable item (#1675), always compiled, and
  a lazy repeat with a bound of 2 or more over a capturing group (#1676): such a pattern takes no
  other reader's spelling early, nor remembers a timeout or the interpreter's cost, and so is read
  on its own reader's length and units scanned alone, as on `main`.
- **The shipped lists are read-only on both builds.** netstandard2.0 wraps its `HashSet<string>` in
  an `ISet<string>` whose edits throw `NotSupportedException`, as `FrozenSet<T>`'s do, and whose
  reads — `IsSubsetOf` and the rest 0.7.0's `HashSet` answered — still answer; `Adopt` still copies
  it, so the filter never hands out the set behind it. A cast to `HashSet<string>`, which 0.7.0's
  netstandard2.0 build allowed, now fails, as it always did on net10: a set no edit reaches cannot
  be a `HashSet<T>`, whose `Add` no subclass can refuse.
- **#1676 is closed as a limit of .NET's compiled engine, on the maintainer's decision of
  2026-10-09.** It keeps the capture of an iteration a lazy repeat with a bound gave up —
  `.([a-z]){,2}?I|` over `1ai` gives `'a'` — and loops for good, its timeout notwithstanding, on
  `.([a-z]){1,3}?I|` over `" 1baxa"`; 0.7.0, which compiled the pattern as written, does both. A
  fuzz found `{0,2}?`, `{0,3}?` and `{1,2}?` keeping a capture, and `{0,1}?`, `{1,1}?`, `*?` and
  `{1,}?` right. `docs/equivalence.md` says so, and a test pins the reading.
- **#1675 is closed as a limit of .NET's engines, on the maintainer's decision of 2026-10-09.** Both
  engines misread patterns repeating an empty-capable item, each on different ones: the compiled one
  on the issue's pattern, the interpreter on `(?:\D.|)+?\w|x`, where it starts a match at 1 from 0,
  and on `(?:a|)+?.+|x`, where it loops. Choosing an engine cannot be right on all of them;
  `docs/equivalence.md` says so, and a test pins the reading.

## Rejected

- **Interpreting every pattern that repeats an empty-capable item**, for #1675: right on the issue's
  pattern, wrong or looping on the two above.
- **Interpreting every pattern with such a repeat**, for #1676: an interpreter bounded at 1 s falls
  back to the compiled engine where it runs out, so a text's tokens came to hang on the texts read
  before it; unbounded, it runs on where the release refused after a second; and a long document
  ran interpreted where the release ran compiled.
- **Writing the repeat out**, `X{0,2}?` as `(?:X(?:X')??)??` with `X'` numbering its groups as `X`
  does, for #1676: it matched an empty-capable item otherwise than Python, renumbered the `(1)` of a
  conditional, which .NET then refused, and nested repeats grew the pattern to megabytes.
- **Wrapping the group otherwise**, for #1676: `(?:([a-z])){0,2}?` and `(?:([a-z])|(?!)){0,2}?` keep
  the stale capture too.
