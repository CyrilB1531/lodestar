# The Onnx findings of the Review B after #1583

**Issues:** [#1589](https://github.com/CyrilB1531/lodestar/issues/1589),
[#1590](https://github.com/CyrilB1531/lodestar/issues/1590).
**Status:** written with the work, 2026-09-29.
**Date:** 2026-09-29.

## The problem

The Review B of `Lodestar.Onnx` after #1583, on `main` at `f3bacc88`, found two defects:

- A model fixing both its batch and its sequence axis decides every chunk alone, yet a chunk past
  one array was refused on every call, under `inputIds`, `options`, `encoder` or `batch` — an
  argument no value could make pass; the comment claiming the width came from `options` was false
  for it.
- The `Embed` page priced the output at 4 × the dimension a cell, true only for a float output:
  a float16 or bfloat16 one is 2 × the dimension plus the rented `float` array it is widened into,
  a pooled output is priced per row, and the token-type buffer stays with the thread.

## Decisions

- **Refused when opened, under `modelPath`.** Two fixed axes whose product passes one array are
  refused by the constructor, the session released on the way out. A model fixing one axis at most
  still meets the refusal per call — a fixed batch with the caller's length, or a fixed sequence
  with the caller's batch size — so the argument named is the one whose value would change the
  outcome.
- **A second fixture, `tiny_embedder_huge_batch.onnx`**, fixes only the batch at 65,536: a
  32,768-token input reaches the per-call refusal. `tiny_embedder_huge_static.onnx` now pins the
  constructor's.
