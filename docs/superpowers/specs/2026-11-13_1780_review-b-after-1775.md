# The Review B after #1775: `only_second` at or below the template, `processing_kwargs` and constructor fields

**Issue:** [#1780](https://github.com/CyrilB1531/lodestar/issues/1780).
**Status:** written with the work, 2026-11-13.
**Date:** 2026-11-13.

## The problem

The Review B after #1775 ran sentence-transformers 6.2.0, transformers 5.5.4 and tokenizers 0.22.2 against a C#
probe of `Lodestar.Onnx` and found six gaps against the rules of
[the #1257 spec](2026-11-08_1257_onnx-embedding-truncation.md):

1. A configured `only_second` at or below the template refused texts sentence-transformers embeds.
2. `processing_kwargs` that fail every `Transformer.preprocess` call were read past: an `image`, `audio` or `video`
   bucket `dict.update` refuses, a key that is not a string, and a `stride` the tokenizer refuses.
3. Constructor fields `load_config` and `_load_init_kwargs` refuse at load were read past.
4. Decision 0001 and `THIRD-PARTY-NOTICES.md` say `System.Text.Json` is declared by `Lodestar.Text` and
   `Lodestar.Embeddings` alone, where `Lodestar.Onnx` declared it on netstandard2.0.
5. The `GenerateAsync` page said a text past the model's limit is cut, not refused, false below the template.
6. The `only_second` refusal tokenized the whole corpus before refusing, with a message of its own.

## Decisions

- **Under `only_second`, a length at or below the template takes the ordinary path** (finding 1): the encoder
  `WithDefaultMaxLength` gives, which leaves a row whole below the template and cuts every text to it at the
  template, as tokenizers' `max_length − 2` wraps below it and is 0 at it. Past the template, a text past the length
  is refused, as before. The template is the count `Encode("")` returns, read only on that path.
- **`image`, `audio` and `video` are validated as `text` is** (finding 2): a bucket Python finds true reaches
  `dict.update` and is refused where that refuses it; nothing of it is read, since the tokenizer's call takes only
  `text` and `common` (`_call_single_modality_processor`). A key that is not a string, in a list of pairs of the `text`
  or `common` bucket, is refused, as `**call_kwargs` refuses it; `NaN` and `Infinity` are floats there.
- **`stride` is refused where tokenizers refuses it, and only there** (finding 2). It is read from the merged buckets
  where the truncation cuts: not a JSON integer from 0 to `2⁶⁴ − 1` (a boolean counting as 0 or 1) is refused at
  every call; so, where the length `L` handed to tokenizers is at least the template's `t` tokens, is one past
  `L − t`, as `with_truncation` refuses it; one equal to `L − t`, from 1, refuses each text past `L`, as
  `Encoding::truncate` panics on it, through the path `only_second` takes. `L` is the length the file states, before
  rule 2's cap, else the default. A refusal at every call is an `InvalidOperationException`, as rule 5's are.
- **The constructor fields sentence-transformers refuses at load are refused** (finding 3, rule 5): the six kwargs
  fields as the table above, the field a new name and its old one leave being the old one's; a `modality_config` that
  is not an object, or beside no `module_output_name`, or whose kept entries are not objects naming `method` and
  `method_output_name`; a `transformer_task` outside the six names. A value that loads and fails only at encode is
  read past, as the rule asks no more than the load's refusals: a `modality_config` naming neither `text` nor
  `message`, a `method` or `module_output_name` that is not a string, measured failing every text, and a task the
  model's architecture has no head for (`any-to-any` on a Bert), which fails on the architecture, not the file.
- **`Lodestar.Onnx` declares no `System.Text.Json`** (finding 4): on netstandard2.0 it reaches it through its
  `Lodestar.Embeddings` reference, so decision 0001 and the notices hold again; the nuspec check expects what it did
  before #1775.
- **The `GenerateAsync` page says where a text is cut and where it is refused** (finding 5): below the template a row
  past the model's limit stays refused, under rule 7.
- **The `only_second` path encodes one text at a time and stops at the first past the length** (finding 6), naming
  `texts` in the encoder's own wording, `The text at position i is refused: …`; the ordinary path is unchanged.

## Measured

The same 335 configurations replayed through `EmbedBatch` on `tiny_embedder.onnx`, a model with no table, with the
same five texts, the probe's word one token as in Python: every refusal and every cut length agrees with
sentence-transformers but in the cases the decision on finding 3 reads past, seven refused by Python at every text and
the encode-time failures it meets after loading, and five whose length Python takes from its table of twelve, where
the C# model has none and takes 256. `main` disagreed on 195 of them. `EmbedBatch`'s
per-call path, 32 texts on one pinned core, 40 runs of 3000 calls interleaved: options overload median 76.2 µs against
`main`'s 78.4, encoder overload 75.4 against 75.5; allocation per call unchanged.

## Settled

- Every point the [#1257 spec](2026-11-08_1257_onnx-embedding-truncation.md#settled) settles still holds: the
  emulation of Python's `json`, a null `MaxLength` capping nothing on `BatchEncoder` itself, an empty batch under a
  template longer than the default, and the generator naming `encoder` for an explicit `MaxLength` past the limit.
- A key the constructor does not take stays read past, as #1257 decided; finding 3 refuses only the shapes of fields
  it takes.
- `stride` is checked against the uncapped length where the file states one past the model's limit, as tokenizers
  checks it; the rows are still cut at the cap, rule 2's divergence. Where the file states none, the check takes the
  default, 256 capped, as the cut does, where sentence-transformers would take the tokenizer's `model_max_length`.
