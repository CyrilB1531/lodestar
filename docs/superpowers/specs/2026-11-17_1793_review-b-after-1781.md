# The Review B after #1781: `only_second` handed no length, constructor fields, `processing_kwargs` and lengths

**Issues:** [#1793](https://github.com/CyrilB1531/lodestar/issues/1793),
[#1794](https://github.com/CyrilB1531/lodestar/issues/1794),
[#1795](https://github.com/CyrilB1531/lodestar/issues/1795),

**Status:** written with the work, 2026-11-17.
**Date:** 2026-11-17.

## The problem

The Review B after #1781 ran sentence-transformers 6.2.0, transformers 5.5.4 and tokenizers 0.22.2 against
`Lodestar.Onnx` and found four gaps against the rules of
[the #1780 spec](2026-11-13_1780_review-b-after-1775.md):

1. Under `only_second` with no length handed to tokenizers, every text was cut at the model's limit, where Python
   cuts none and a stated length of 40 was still refused at that limit (#1793).
2. `query_expansion`, `query_length`, `model_name_or_path` and `tokenizer_name_or_path`, which sentence-transformers
   refuses at load, were read past (#1794).
3. A truthy `processing_kwargs` Python cannot take as a set was refused only at the first text (#1795).
4. A `max_seq_length` or `model_max_length` that loads and fails each encode was refused at load (#1796).

## The reference

Measured on sentence-transformers 6.2.0 from its wheel, transformers 5.5.4, huggingface_hub 1.33.0, tokenizers
0.22.2 and torch, offline, over a saved Bert whose position table holds twelve rows and whose template is two tokens;
each text encoded alone, `""`, one, three, eight and twenty words; `encode([])` alongside.

| `max_seq_length` or `model_max_length` | Result |
| --- | --- |
| an integer of at least 1 | a length, as before |
| `0`, `-0`, `true`, `false` | loaded, nothing cut |
| an integer or a float past `10²⁰`, `Infinity` included | loaded, nothing cut: transformers' `LARGE_INTEGER` |
| any other float, `NaN`, `-Infinity`, `0.0` and `1e20` among them; a negative integer; `2⁶⁴` to `10²⁰` | loaded; each encode fails where the truncation cuts, or a `max_length` padding pads, and the call states no `max_length` |
| a string, a list, an object | loaded; each encode fails whose call states no `max_length`, whatever the truncation |

`encode([])` returns `[]` in every row. The two fields agree in every row but `null`, which `max_seq_length` reads as
none stated and `model_max_length` as no limit; a null `model_max_length` beside a `max_seq_length` of 7 wins, the
kwargs replacing it, measured cutting nothing under `only_second` (Review A pass 58).

| `query_expansion` `token` a string not in the tokenizer's vocabulary | `ValueError` at load |

## Decisions

- **`only_second` handed no length cuts nothing** (#1793): the encoder is left uncut, so a text past the model's limit
  is refused by it under the overload's own argument, as the stated length of 40 already was. Under any other
  strategy, one that cuts nothing included, no length handed still cuts at the model's limit, rule 2's divergence.
- **The four constructor fields are refused where sentence-transformers refuses them at load** (#1794), in its order:
  `model_name_or_path` after the kwargs and before `__init__`, `tokenizer_name_or_path` after the
  `processing_kwargs` check, `query_expansion` and `query_length` last. A relative `tokenizer_name_or_path` names a
  folder from the directory current when the embedder was constructed, as Python resolves it at load; where that
  directory is gone, only a rooted path can name one. Without a `modality_config`,
  an unknown `transformer_task` is named before the kwargs, as `load_config` looks its defaults up first. `huggingface_hub`'s `validate_repo_id` is written out: one
  `/` at most, each part 1 to 96 ASCII letters, digits, `_`, `-` and `.`, opening and closing on a letter, a digit or
  `_`, no `--`, no `..`, no closing `.git`.
- **A truthy `processing_kwargs` Python cannot take as a set is refused at load** (#1795): a number, a boolean or a
  named literal, or a list holding a list or an object; a list or a string it can take stays refused at the first
  text, as #1780 decided.
- **What loads and fails only at encode is refused at the first text** (#1796), the #1780 rule applied to the
  lengths: the configured length is kept as an encode-time refusal and dropped where Python never hands it — a call
  `max_length` over it, or no truncation and no `max_length` padding — except a string, a list or an object, which
  stays refused under any truncation unless the call states a `max_length`. A float past `10²⁰` is no limit, as an
  integer past it already was. Zero and booleans stay refused at load, as #1257 settled for zero and `true`.
- **A `padding` transformers refuses is refused at the first text, and a stride is checked only where a length reaches
  tokenizers**: both close the measured rows above in the method this change rewrites. Beside a stride it refuses,
  a length it refuses is the one named, as transformers compares a string length first and `enable_truncation`
  takes `max_length` before `stride`, measured (Review A pass 4).

## Measured

502 configurations replayed through `EmbedBatch` on `tiny_embedder.onnx` against the table above, each text alone and
the empty batch, the 22-token row compared only as cut or past the table, since the C# fixture has no table: `main`
disagreed on 374; the branch on 65, all settled below — 48 zero or boolean lengths, 6 tokenizer folders or
repository ids, 3 string tokens, 7 `max_length` paddings that change the padded shape and not the vector, or fail past
the table, and one `only_second` row where Python takes the tokenizer's `model_max_length` and the C# fixture the
default 256.

## Settled

- Every point the [#1780 spec](2026-11-13_1780_review-b-after-1775.md#settled) and the
  [#1257 spec](2026-11-08_1257_onnx-embedding-truncation.md#settled) settle still holds.
- Zero, `-0`, `true` and `false` as a length are refused at load, where sentence-transformers loads them and cuts
  nothing: #1257 settled zero and `true`, and `-0` and `false` are the same values to Python. A call `max_length` of
  one of them is refused at the first text, where it cuts or a `max_length` padding pads to it, on the same rule,
  where Python cuts nothing or pads to it, measured (Review A pass 7).
- A `tokenizer_name_or_path` naming a folder or a valid repository id is read past: what loads from it is a tokenizer
  Lodestar never reads, the caller passing its own. So is a string `query_expansion` token, which Python checks
  against that tokenizer's vocabulary, and a `token` of `null` on a tokenizer with no mask or end token.
- A `max_length` padding pads every row to a length in Python; Lodestar pads each sub-batch to its longest row, which
  changes the vector of no row. Past the model's limit Python fails every text there, where Lodestar cuts at the
  limit: rule 2's divergence.
- The FlashAttention check on `query_expansion` reads the loaded model's attention implementation, which an ONNX
  graph does not carry; it is not emulated.
- `validate_repo_id` is huggingface_hub 1.33.0's, the release transformers 5.5.4 ran with here: ASCII only, under
  `re.ASCII`, 96 characters a part, `fullmatch`, measured refusing `café`, `abc\n` and a namespace of 97. The 1.31.0
  in `.venv-oracles` predates those flags; it is not the reference (Review A pass 1).
- A relative `tokenizer_name_or_path` folder is looked up when the configuration is read, at the first text, from
  the directory current at construction — a path relative to another Windows drive from that drive's directory then
  — as every file the configuration names is read then
  ([#1257](2026-11-08_1257_onnx-embedding-truncation.md), pass 6), where Python looks at load (Review A pass 1).
- An uncut encoder — a length below the template, or `only_second` handed no length or a length past the model's
  limit — has every text encoded whole first; the first row past the model's limit is then refused before any padding or
  sub-batch runs, in `Run`'s wording with the text's position and under its argument, so no inference is wasted and no padded block is
  allocated for a refused row (Review A passes 2 and 42).
- `Stated` keeps its flags — `AtEncode`, `Unordered`, `HandsNone` beside `RefusesPast`, the last two together meaning `only_second` handed no length (Review A pass 45) — rather than
  one discriminated shape: each producer sets them through one factory, and recasting the record is a refactor of the
  reader beyond these four findings (Review A pass 5).
- A float is read by `double.TryParse`, which rounds correctly from .NET Core 3.0 and, on .NET Framework, may not
  for a mantissa past 17 digits; only a length within an ulp of `10²⁰` spelled that long falls on the other side of
  `LARGE_INTEGER` there. Where .NET Framework refuses a float, it is past the double range, an underflow reading as
  zero, so a non-zero mantissa is an infinity (Review A pass 6).
- A relative `tokenizer_name_or_path` is combined with the directory captured at construction and nothing more: on
  Windows a path rooted without a drive (`\tok`) or on a drive without a root (`C:tok`) leans on whichever drive or
  directory is current when the configuration is read, which may be a network one, so it is read past unprobed
  (Review A pass 44), and with no captured directory only a rooted path can name a folder. Emulating
  Windows' per-drive directories cost four review passes for a spelling no export writes (Review A passes 7 to 20).
  `..` is resolved lexically, after a link as before it, as .NET resolves every path this reader opens.
- A file string spelled as the marker and a literal's name, `"\u0001NaN"`, is read as that float, the cost #1257
  settled for the reader's emulation of Python's `json`; any other string opening with the marker is a string
  (Review A passes 6 and 8).
- `WithDefaultMaxLength`'s page says how `EmbedBatch` gives an encoder its default length, which holds where it
  gives one; it is not edited for the `only_second` case that gives none (Review A pass 10).
- The reader looks each field up with its own pass over the keys, as it did before this change; a configuration is
  read once per embedder (Review A pass 11). A refusal shows the value it refuses as the file spells it, an object
  whole, as every refusal of the reader does.
- What `WithModelDefault` relies on in a `Stated` — a stated length handed or `HandsNone`, `HandsNone` with no stride,
  an encode-time refusal a refusal — is tested over a grid of 7,712 configurations reaching every kind of
  answer, the call kwargs in the `text` bucket, the `common` one or absent, rather than asserted at run time (Review A
  passes 12 and 31). A configured integer length is parsed twice, so its refusal has one wording.
- A `null` `modality_config` is named before an unknown `transformer_task`: `load_config` asks whether the key is
  present, not what it holds, and fails on `None.items()` before it looks the task up (Review A pass 15).
- On Windows a rooted `tokenizer_name_or_path` spelled as a share or device path, the NT `\??\` form included, or
  on a network drive, is read past without probing it; a relative one is probed from the directory captured at
  construction, the user's own, even where that is a share (Review A pass 33). Python's `isdir` would reach the host
  the file names; the tokenizer used is the caller's, and an untrusted file should not make the reader open a
  network connection (Review A pass 16).
- Every constructor captures the current directory, the tokenizer-less one included, whose embedder still reads the
  configuration through the overload taking a `BatchEncoder`; the directory has to be the one current at
  construction (Review A pass 17).
- Elsewhere than Windows a share mounted as a folder, or an automounter path such as `/net/host` the probe itself
  mounts, is probed as any folder is: telling it apart takes a file-system query per path that no target exposes
  alike, and the probe is the one Python's `isdir` makes at load (Review A passes 18 and 24).
- A `MaxLength` the caller sets does not lift a refusal of the configuration: a configured length or stride Python
  fails on is refused whatever the caller asks, as `main` refused a bad length at load whatever it asked; the
  caller's `MaxLength` is Lodestar's, not a `processing_kwargs` `max_length` (Review A pass 18).
- A `tokenizer_name_or_path` holding a lone surrogate is refused, where Python on POSIX encodes one from `\udc80` to
  `\udcff` back to a raw byte and may find a folder so named: no export names its tokenizer folder with a byte that
  is not UTF-8 (Review A pass 19).
- The configuration tests share one serial collection because two of them move the current directory, as the class
  did before this change; the grid of 7,712 configurations takes under a second (Review A pass 19).
- `model_name_or_path` is refused, where a key the constructor does not take stays read past as #1257 decided: the
  constructor does take it, the call passing it twice, so refusing it needs no list of the constructor's keys
  (Review A pass 21).
- On Windows a link or a substituted drive that leads to a share is probed as the local path it is spelled as:
  telling it apart takes following the link, which is the probe (Review A pass 21).
- The task refusal is computed once per read, whether or not an earlier field is refused first, so its order lives
  in one place; booleans are read as 0 and 1 only where Python compares them, `query_length`, since a boolean length is
  refused at load (Review A pass 22).
- Where the file states no length, the length a stride and `only_second` are measured against is the default capped
  at the model's limit, as #1780 settled: `Transformer.__init__` caps the tokenizer's own `model_max_length` at the
  position table when none is stated, so Python measures against the capped length too, measured refusing a text
  past twelve under `only_second` on the table of twelve (Review A pass 28).
- `Shown` unquotes a marker-spelled string wherever it stands in a refused value, a key included, the marker cost
  above (Review A pass 30).
- A static export's fixed sequence axis caps the default as the position table does, rule 2 taking the model's limit
  whichever it is; Python, which runs no static graph, caps at the table only (Review A pass 32).
- An empty `query_expansion` token is refused at load, measured: no vocabulary holds it, so the check fails whatever
  the tokenizer (Review A pass 34). The refusal names its length lazily, from two flags, as pass 29 asked, rather
  than from a string built at the call (Review A pass 34).
- The rule that what fails only at encode is refused at the first text covers the lengths and the
  `processing_kwargs`; a `modality_config` that loads and fails or converts each encode, holding a `message` entry or
  naming neither `text` nor `message`, stays read past, as #1780 decided (Review A pass 35).
- The refusal tells a default length capped at the model's limit from the number, `length` below 256, which holds
  because a `Stated` with no `Handed` states no length, the grid's invariant (Review A pass 39).
- A row past the model's limit under an uncut encoder names `options` or `encoder`, as #1423 and #1780 named it:
  that is the argument whose length lets the row through (Review A pass 43).
- The text overloads hold their longest row to the model's limit up front only where the encoder cuts at no length
  within it, as pass 43 asked; `Run` holds every row to it whatever the caller (Review A pass 44).
- The generator test disposes its embedder twice, by its `using` and by the generator owning it, the convention the
  test file documents and the ownership contract makes safe, which CA2000 enforces (Review A pass 46).
- The text overloads encode the whole corpus before holding its longest row to the model's limit, `EncodeAll` being
  `Lodestar.Embeddings`' and the row's position named all the same (Review A pass 48).
- The up-front scan of the longest row is one pass over the lengths, which tokenizing dwarfs, kept apart from the
  `SortByLength` order; `GetDriveType` on a drive letter answers locally, which the reader asks rather than the
  drive itself (Review A pass 50).
- `PastLimit` takes the article that opens its clause, so one wording serves the refusal standing alone and the one
  following a text's position, as pass 47 asked of the two copies it replaced (Review A pass 53).
- The opening of a text's refusal, `The text at position i is refused:`, is kept alike with `BatchEncoder`'s by
  hand: sharing it through `src/Shared` would change `Lodestar.Embeddings`, which these issues do not touch (Review A
  passes 53 and 55).
- `IsNamedLiteral` reads an element's raw text each time it is asked, a list item included, once per embedder's
  read (Review A pass 56).
- The reader takes from the call kwargs only the four that decide where a text is cut, as #1257 decided; another
  kwarg that changes the vectors or fails each encode, `add_special_tokens` or `pad_to_multiple_of`, stays read past
  (Review A pass 57).
- A text refused by the model's limit under an uncut encoder names `encoder` through the generator, not `values`,
  as its page says, the argument whose length lets the row through; and where `only_second` refuses a later text past
  its length while encoding, that one is named first, as tokenizers refuses it in `preprocess` before the graph meets
  an earlier row past the table (Review A pass 59).
- `Source` is set wherever a configured `Stated` leaves `Cut`, a stride beside it or not, as pass 53 asked; the
  bucket merge returns its reason or its fields, never both, as a pair, as pass 52 asked rather than an `out`
  (Review A pass 60).
- `TextIs` answers a lone surrogate as no match by catching what `ValueEquals` throws, once per name compared, in a
  read made once per embedder of a file no export writes so; `Unlimited` keeps `int.MaxValue` as its length, which
  the capped default the other strategies cut at is computed from; and the reader stays one class, its Python
  emulation, probes and rules side by side as before this change (Review A pass 61).
- Whether a local folder a relative `tokenizer_name_or_path` names exists decides the refusal, as Python's `isdir`
  decides its load; and a caller's `MaxLength` below its template cannot reach the up-front scan, `BatchEncoder`
  refusing it when built (Review A pass 62).
- Handed no length, `false` or `do_not_truncate` cuts at the model's limit while `only_second` cuts nothing: the cap is
  #1257's rule 2, and `only_second` is read as Python reads it, the maintainer's word, Cyril 2026-11-13 (Review A
  pass 1).
