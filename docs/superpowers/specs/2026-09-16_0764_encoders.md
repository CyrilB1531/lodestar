# 0764 — `OneHotEncoder`, `OrdinalEncoder` and `SimpleImputer`

**Status:** written before the work, 2026-09-16.

Issue: [#764](https://github.com/CyrilB1531/lodestar/issues/764).

Reading: [decision 0132](https://github.com/CyrilB1531/lodestar/blob/53af23c2/docs/decisions/0132-preprocessing-writes-splitters-scalers-and-encoders-and-not-smote.md),
which writes the encoders and the imputer on the framework-free argument and only that one. Not amended or applied
since. `sklearn.preprocessing` and `sklearn.impute` 1.9.0 read by probe, not from the documentation.

## Problem

Nothing here is absent from .NET. ML.NET has `OneHotEncoding`, `MapValueToKey` and
`ReplaceMissingValues`, each behind an `IDataView` and a column name; SharpLearning's
`OneHotTransformer` and `ReplaceMissingValuesTransformer` work on its own CSV rows. **What is absent is a call that
takes an array and returns one** — the same finding `StandardScaler` recorded, and the only argument this lot rests on.

## What the reference does, measured

1. **`OneHotEncoder`**: `categories_` is the **sorted** distinct values per feature, and the output carries one column
   per category in that order. Measured on `['b','a','c','a']`: categories `['a','b','c']`, and `'b'` encodes to
   `[0, 1, 0]`.
2. **`drop`**: `'first'` drops each feature's first category, so it encodes to all zeros — `'a'` becomes `[0, 0]`.
   `'if_binary'` drops the first **only where the feature has exactly two categories**: measured, a three-category
   feature keeps all three columns under the same setting.
3. **`handle_unknown`**: `'error'` raises naming the column; `'ignore'` encodes an unseen value as **all zeros**,
   which is the same row a dropped first category produces — a collision the reference accepts and the page must say
   out loud.
4. **`OrdinalEncoder`** maps to the index in that same sorted order: `'c'` → 2, `'a'` → 0.
5. **`SimpleImputer`**: `mean`, `median`, `most_frequent`, `constant` (default fill 0). The median of an even count is
   the average of the two middle values, which is `numpy.median` and so the type-7 percentile at 50 — the one
   `Percentile.Median` already computes for [`RobustScaler`](../../reference/preprocessing/scaling/robustscaler.md).
   **`most_frequent` breaks a tie toward the smaller value**: measured on `[1, 1, 2, 2, NaN]`, the fill is 1.
6. **An all-`NaN` column has no statistic**, and by default the reference **drops that column from the output** —
   three columns in, two out. `keep_empty_features=True` keeps it and fills it with 0.

## Placement

`Lodestar.Preprocessing`, beside the scalers. **One element type per call**, which is what the reference does too: a
2-D numpy array carries one dtype, and mixing types is a DataFrame's job. A caller with a string column and an integer
column makes two calls and concatenates, and the page says so rather than inventing a column-spec object.

```csharp
public sealed class OneHotEncoder<T> where T : IComparable<T>, IEquatable<T>
{
    public static OneHotEncoder<T> Fit(ReadOnlySpan<T> values, int featureCount, OneHotEncoderOptions options = null);
    public double[] Transform(ReadOnlySpan<T> values);
    public int FeatureCount { get; }
    public int SampleCount { get; }
    public int EncodedFeatureCount { get; }
    public IReadOnlyList<IReadOnlyList<T>> Categories { get; }
}
```

- **Generic rather than two copies.** `string` and `int` are the two the issue names, and a generic constrained on
  `IComparable<T>` and `IEquatable<T>` covers both with one algorithm. The repository already ships a generic public
  type (`LodestarVectorStoreCollection<TKey, TRecord>`), so the reference gate handles the arity.
- `OrdinalEncoder<T>` has the same shape and returns `double[]` too, so the two compose with the scalers without a
  conversion.
- `SimpleImputer` is **not** generic: it fills `NaN` in a `double` matrix, and `NaN` is what marks a missing value.
- **Rejected:** a non-generic `OneHotEncoder` over `string` alone, with integers stringified by the caller. It makes
  `1` and `"1"` the same category and loses the sort order that decides the column layout.
- **Rejected:** sparse output. `CsrMatrix` is where that belongs and it is [#765](https://github.com/CyrilB1531/lodestar/issues/765)'s
  scope, not this lot's.

## The one divergence, and why

**An all-`NaN` column is refused rather than dropped.** The reference returns a matrix one column narrower than the
one it was given, so a caller who computed a feature count up front is wrong afterwards, silently. Options weighed:

1. **Reproduce the drop.** Parity, and a `Transform` whose output width depends on the *fitted data* rather than on
   the input shape — in a typed API that is a trap, and `EncodedFeatureCount` would have to explain it.
2. **Always keep the column and fill it with 0**, which is the reference's own `keep_empty_features=True`. Parity with
   that setting, none with the default.
3. **Refuse the column at `Fit`**, naming it, and offer `KeepEmptyFeatures` for callers who want the reference's
   `True` behaviour. A column with nothing in it has no statistic to impute from; refusing says so where dropping
   hides it.

**Chosen: 3.** `docs/equivalence.md` carries the row, and the message names the column and the option.

## Evidence

- **`preprocessing_encoders.json`** from `sklearn.preprocessing` and `sklearn.impute`: one-hot over string and integer
  columns, each `drop` setting including the three-category case that `if_binary` must *not* drop, both
  `handle_unknown` branches, two features at once so the column layout is pinned; ordinal encoding over the same;
  and the imputer's four strategies, with an even-count median, a `most_frequent` tie, and a custom fill. Compared
  exactly for indices and layout, at 1e-9 for the imputed values.
- **Edge tests:** every refusal, the all-zeros collision between an ignored unknown and a dropped first category, the
  tie rule, and a `Transform` on a shape the encoder was not fitted for.
- **Benchmark:** `EncoderIncumbentBenchmarks` against ML.NET 5.0.0's `OneHotEncoding` and `ReplaceMissingValues`, the
  incumbents the issue names, fit and values-read as [`bench/README.md` §45](../../../bench/README.md) does for the
  scalers — its estimator is lazy the same way.
