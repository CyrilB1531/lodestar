# 0687 — `NanPolicy` on the families scipy gives it to

**Status:** accepted, 2026-09-12. Written before the work.

**Issue:** [#687](https://github.com/CyrilB1531/lodestar/issues/687), opened on the
`docs/equivalence.md` row that records the gap.

## Problem

scipy's `nan_policy` is `'propagate'` (return `nan`), `'raise'`, or `'omit'` (drop the missing
observations and test on the rest). A caller arriving from scipy with real data arrives with
missing values, and today this package has no answer: the sample either contains a `NaN` and
produces one, or the caller filters by hand.

Filtering by hand is where it goes wrong. For a paired test, `'omit'` has to drop **pairs**, not
values — dropping each sample independently silently changes what is being tested, and produces a
number rather than an error.

## What the tree already does

`docs/equivalence.md`'s `nan_policy` row already records more than the issue quotes: **nine of the
ten families follow scipy's own default (`'propagate'`) exactly**, and `ChiSquare.Contingency` is
the one exception, refusing a `NaN` cell because a contingency table's cells are counts and the
expected-frequency table divides by their marginals.

So `'propagate'` is not a feature to add. It is the shipped behaviour, already documented as
parity, and the default this work must not disturb.

## Measured: which scipy functions actually take `nan_policy`

The issue says "every test above takes `nan_policy` in scipy". Checked against scipy 1.18.1 by
reading the signatures rather than the documentation:

| scipy | `nan_policy` | this package |
| --- | --- | --- |
| `ttest_ind`, `ttest_rel`, `ttest_1samp` | yes | `TTest.Independent`, `.Paired`, `.OneSample` |
| `mannwhitneyu` | yes | `MannWhitney.Test` |
| `wilcoxon` | yes | `Wilcoxon.Paired`, `.OneSample` |
| `f_oneway` | yes | `OneWayAnova.Test` |
| `kruskal` | yes | `KruskalWallis.Test` |
| `shapiro` | yes | `ShapiroWilk.Test` |
| `ks_2samp` | yes | `KolmogorovSmirnov.TwoSample` |
| `chisquare` | yes | `ChiSquare.GoodnessOfFit` |
| `chi2_contingency` | **no** | `ChiSquare.Contingency` |
| `fisher_exact` | **no** | `FisherExact.Test` |
| `false_discovery_control` | **no** | `MultipleComparisons.*` |

Eleven entry points get the parameter. Five do not, and that is parity rather than an omission —
scipy withholds it from exactly those three functions. It also leaves `ChiSquare.Contingency`'s
existing `NaN` refusal untouched, which is the behaviour `docs/equivalence.md` already documents.

## Decision

**A `NanPolicy` enum in `Lodestar.Stats`, three-valued, matching scipy's shape.**

```csharp
public enum NanPolicy { Propagate = 0, Raise, Omit }
```

`Propagate` is the default on all eleven entry points, so no existing call changes behaviour, and
`Propagate = 0` makes `default(NanPolicy)` the same thing.

Parity with the library a caller migrates from is this repository's standing tie-breaker
([decision 0008](../../decisions/0008-italian-enza-nltk-divergence.md)). It is what settles the
argument against the enum — that `'propagate'` and `'raise'` are each one line at a call site, so
only `'omit'` carries content. True, and outweighed: a caller porting a script wants the parameter
their script already passes, and a two-valued subset of a three-valued scipy parameter is a
divergence to explain rather than a simplification to enjoy.

`Raise` throws `ArgumentException`, the package's idiom for a refused input.

### Omit, measured against scipy rather than reasoned about

| entry point | omission |
| --- | --- |
| `TTest.Paired`, `Wilcoxon.Paired` | **listwise** — drop the index when either side is `NaN` |
| `ChiSquare.GoodnessOfFit` when `expected` is given | **listwise**, the two being aligned |
| the other eight | **per-sample** |

Verified by execution, not by reading the docs. `ttest_rel` on
`a = [1, 2, NaN, 4, 5]`, `b = [2, NaN, 3, 5, 7]` with `nan_policy='omit'` returns
`statistic = -4.0, df = 2` — three pairs kept, identical to filtering listwise by hand, and not
what dropping each sample independently gives. `wilcoxon` agrees. `ttest_ind`, `mannwhitneyu`,
`ks_2samp` and `chisquare` all match per-sample filtering.

### Omit is a filter, not a second policy

Omission runs first; the family's existing guards then run unchanged on what survives.
`ShapiroWilk.Test` still raises below `n = 3`, and `KruskalWallis.Test` still raises on a fully
tied pooled sample — the two places `docs/equivalence.md` records this package raising where scipy
returns `(nan, nan)` with a warning.

The alternative, answering scipy's `(nan, nan)` on a path reached only through omission, was
rejected: it makes one degenerate input raise or not depending on how it arrived, and contradicts
the reasoning behind both guards on a path they were never argued about. Omit changes which values
are tested, never what a degenerate result means.

### `GoodnessOfFit` with an explicit `expected` will commonly raise under Omit

`chisquare` requires the observed and expected frequencies to sum to the same total, and omission
breaks that precondition by construction — remove an observation and its expectation and the two
sums move by different amounts. scipy raises `ValueError`; this package already raises for the same
reason. So `Omit` on that overload is expected to raise more often than not, and a caller wanting
it should filter and rescale `expected` themselves.

This is recorded because it was found by running the case, not by reading either library, and it
is the kind of thing a caller meets as a surprise.

## Two entry points that look aligned and are not

`Wilcoxon.OneSample` takes differences, one sample, so it filters per-sample.
`ChiSquare.GoodnessOfFit` with `expected` left `default` compares against a uniform expectation
scipy derives from the observations, so it also filters per-sample — the aligned case is only the
explicit-`expected` overload.

## Implementation

One internal helper, `src/Lodestar.Stats/Internal/NanFilter.cs`: per-sample and listwise
filtering, spans in and arrays out. It stays in `Lodestar.Stats` rather than `src/Shared/`,
because no other package needs it and `src/Shared/` is compiled into all sixteen.

Each entry point gains a trailing `NanPolicy nanPolicy = NanPolicy.Propagate` parameter and, for
`Omit`, filters before its existing guard block. `Propagate` adds no work at all: the value falls
through untouched, which is what nine families already do.

## Testing

Oracle-validated against scipy for all three values on every entry point that takes the parameter,
per the issue's acceptance criteria. The corpus covers, per family: a clean sample under each
policy; a sample holding a `NaN` under each policy; and for the two paired families, a case where
listwise and per-sample filtering give **different** answers, so the corpus would catch the wrong
one rather than agreeing with either.

Two cases are asserted in the C# suite rather than the corpus, because scipy does not produce a
value to freeze: `ShapiroWilk.Test` where omission leaves fewer than three observations, and
`KruskalWallis.Test` where it leaves a fully tied pool. Both must raise, which is the decision
above made checkable.

## Documentation owed, in the same commit as the code

- A parameter row and a `<remarks>` sentence on each of the eleven reference pages under
  `docs/reference/stats/tests/`.
- `docs/equivalence.md`'s `nan_policy` row rewritten. It currently reads "None of the ten families
  here offers it", which this work makes false; the replacement names the eleven that take it, the
  five that do not and why scipy withholds it there, and keeps the `ChiSquare.Contingency`
  sentence, which stays true.
- The stats guide states what happens to a `NaN` by default.
- One `CHANGELOG.md` entry under `### Lodestar.Stats`, `#### Added`.
- ADR **0116**, the next free number.

## Not in scope

- **No version bump.** `Lodestar.Stats` releases separately; `check_unreleased.py` treats
  unpublished work as the normal state.
- **`ChiSquare.Contingency`, `FisherExact.Test` and `MultipleComparisons.*` are untouched**, for
  the reason measured above.
- **No `axis` parameter.** scipy's `nan_policy` is part of an array-API surface that also carries
  `axis`; this package takes spans and single samples, and `axis` has no meaning here.
