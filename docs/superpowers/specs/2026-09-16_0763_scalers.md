# 0763 — `MinMaxScaler`, `RobustScaler` and `MaxAbsScaler`

**Status:** accepted, 2026-09-16. Written before the work.

Issue: [#763](https://github.com/CyrilB1531/lodestar/issues/763).

Reading: [decision 0132](../../decisions/0132-preprocessing-writes-splitters-scalers-and-encoders-and-not-smote.md),
which writes the remaining scalers beside `StandardScaler`. Not amended or applied since.

## Problem

`StandardScaler` centres on the mean and scales by the standard deviation, which is the wrong pair for two common
shapes: data with outliers, where the mean and the deviation both move with them, and data whose zeros are meaningful,
where centring destroys sparsity. scikit-learn answers both with `RobustScaler` and `MaxAbsScaler`, and answers the
bounded-range case with `MinMaxScaler`.

ML.NET has `NormalizeMinMax` and `NormalizeRobustScaling`, both reached through an `IDataView` or a catalog naming
columns; SharpLearning's `MinMaxTransformer` works on its own `F64Matrix`. **The capability is not missing, the
array-in array-out entry point is** — the same finding `StandardScaler` recorded, restated for three more scalers.

## What the reference does, read from `sklearn.preprocessing._data` 1.9.0

1. **`MinMaxScaler(feature_range=(0, 1), clip=False)`**: `data_min_`, `data_max_`, `data_range_ = max − min`;
   `scale_ = (high − low) / _handle_zeros_in_scale(data_range_)`; `min_ = low − data_min_ · scale_`.
   `transform` is `X · scale_ + min_`, then `clip(X, low, high)` when `clip` is set; `inverse_transform` is
   `(X − min_) / scale_` **and never clips**.
2. **`MaxAbsScaler(clip=False)`**: `max_abs_ = nanmax(|X|)`, `scale_ = _handle_zeros_in_scale(max_abs_)`;
   `transform` is `X / scale_`, clipped to `[−1, 1]` when `clip` is set; `inverse_transform` is `X · scale_`.
3. **`RobustScaler(with_centering=True, with_scaling=True, quantile_range=(25, 75), unit_variance=False)`**:
   `center_ = nanmedian(X)`; `scale_ = percentile(q_max) − percentile(q_min)` through `np.nanpercentile`, then
   `_handle_zeros_in_scale`; with `unit_variance`, divided by `Φ⁻¹(q_max/100) − Φ⁻¹(q_min/100)`.
   `transform` subtracts then divides, `inverse_transform` multiplies then adds — **in that order**, which matters
   because both steps are optional and the composition is not symmetric if they are reordered.
4. **`_handle_zeros_in_scale` is not `scale == 0`**, and this is the rule a reimplementation gets wrong: with no
   `constant_mask` given — which is the case for all three of these, `StandardScaler` being the one that passes one —
   it replaces every scale **below `10 · eps`** (`2.22e-15`) by 1. A feature whose range is `1e-16` therefore scales by
   1, not by `1e16`.
5. **`np.nanpercentile` interpolates linearly** (`method="linear"`, Hyndman–Fan type 7): at `h = (n − 1)·q/100`,
   the value is `x[⌊h⌋] + (h − ⌊h⌋)·(x[⌊h⌋+1] − x[⌊h⌋])` over the sorted column. Neither quantile already in this
   repository is that convention — `SplitConformal.Quantile` takes the conformal order statistic `⌈(n+1)(1−α)⌉`, and
   `Lodestar.Metrics`' `WeightedPercentile` is the averaged weighted percentile scikit-learn's median uses. The type-7
   percentile is written here, internal to the package, and the spec says so rather than letting a reader assume a
   shared helper.
6. **Refusals:** `feature_range` with `low >= high` raises; `quantile_range` outside `0 <= q_min <= q_max <= 100`
   raises. `clip` on `MaxAbsScaler` is a 1.9.0 member, not an invention.

## Placement

`Lodestar.Preprocessing`, beside `StandardScaler`, one options record each and the same three-method shape:

```csharp
public sealed class MinMaxScaler
{
    public static MinMaxScaler Fit(ReadOnlySpan<double> samples, int featureCount, MinMaxScalerOptions options = null);
    public double[] Transform(ReadOnlySpan<double> samples);
    public double[] InverseTransform(ReadOnlySpan<double> samples);
    public int FeatureCount { get; }
    public int SampleCount { get; }
    public IReadOnlyList<double> DataMinimum { get; }
    public IReadOnlyList<double> DataMaximum { get; }
    public IReadOnlyList<double> DataRange { get; }
    public IReadOnlyList<double> Scale { get; }
    public IReadOnlyList<double> Minimum { get; }
}
```

`MaxAbsScaler` carries `MaximumAbsolute` and `Scale`; `RobustScaler` carries `Centre` and `Scale`, **both nullable**
where the reference reports `None` — `with_centering=False` gives `center_ = None` and `with_scaling=False` gives
`scale_ = None`, which is a simpler mapping than `StandardScaler`'s and is stated on the page beside it.

- **Non-finite input is refused**, where the reference allows `NaN` and skips it (`nanmin`, `nanmedian`,
  `nanpercentile`). Refusing rather than propagating because `RobustScaler` sorts: a `NaN` in a column would land
  wherever the sort put it and come back as a percentile nobody asked for, which is worse than either answer.
  `StandardScaler` predates this and propagates instead — a separate inconsistency, recorded in
  `docs/equivalence.md` rather than fixed here, since changing it would change published behaviour.
- **Rejected:** a single `Scaler` type with a mode enum. The five fitted statistics differ per scaler and a shared type
  would make four of them null in every case; the reference's four types are four types for a reason.

## Decided — `unit_variance` takes an edge on `Lodestar.Stats`

`unit_variance=True` divides the scale by `Φ⁻¹(q_max/100) − Φ⁻¹(q_min/100)`. The repository already publishes that
function as `Lodestar.Stats`' `Distributions.NormalQuantile` ([decision 0095](../../decisions/0095-the-stats-numerical-layer-publishes-four-members-and-no-more.md),
published under [0098](../../decisions/0098-the-normal-quantile-is-the-third-member-decision-0095s-rule-publishes.md)),
and `Lodestar.Preprocessing` had no inter-package edge at all.

**Ruled: take the edge** ([decision 0138](../../decisions/0138-lodestar-preprocessing-takes-an-edge-on-lodestar-stats-for-the-normal-quantile.md)),
and `unit_variance` ships in this lot. The floor is `Lodestar.Stats` **0.4.0**, already published and carrying the
member since 0.2.0; the reference is a `PackageReference` with the `LodestarUseProjectRefs` opt-in, the shape
`Lodestar.Stats.TimeSeries` uses.

Two alternatives were put and rejected, and the ADR carries why:

1. **A second normal quantile inside this package** — no edge, and a second implementation of a published member.
2. **Shipping without `unit_variance`**, with an equivalence row and its own issue — honest, and it leaves a published
   scaler one option short of its reference for as long as nobody takes the edge. This was the spec's own
   recommendation before the ruling, and the ruling replaces it.

**One divergence the edge does not remove:** a percentile of 0 or 100 has no finite normal quantile, so
`UnitVariance` with either is refused where the reference divides by an infinity and reports a scale of zero.

## Evidence

- **`preprocessing_scalers.json`** from `sklearn.preprocessing`: each scaler over a matrix with a constant feature, a
  near-constant one at `10·eps` on both sides of the threshold, and an outlier-heavy column; `MinMaxScaler` at
  `(0, 1)` and `(−5, 3)` with and without clipping; `MaxAbsScaler` with and without clipping, including a column that
  is all negative; `RobustScaler` at `(25, 75)` and `(10, 90)`, with each of `with_centering` and `with_scaling` off;
  and the round trip through `inverse_transform` for each. Compared at `1e-9`.
- **Edge tests:** each refusal; the near-constant threshold from both sides; `clip` on a value outside the range and
  the inverse **not** clipping it; a percentile whose `h` falls exactly on an index against one that interpolates; and
  the order the two scale rules apply in — floored to 1 first and divided by the quantiles second, so a constant
  feature under `unit_variance` lands on `1/1.3489795` rather than on 1.
- **Benchmark:** `ScalerIncumbentBenchmarks` against ML.NET 5.0.0's `NormalizeMinMax` and `NormalizeRobustScaling`,
  which is the incumbent the issue names and is already referenced by `bench/Lodestar.Text.Benchmarks`. Both sides
  fit and transform the same matrix, the `IDataView` built in `GlobalSetup`; ML.NET's estimator is lazy in the same
  way its splitter is, so the row that counts is the one that reads the transformed values back.
