# 0765 — `PartialFit` on the scalers, and a `CsrMatrix` overload

**Status:** written before the work, 2026-09-16.

Issue: [#765](https://github.com/CyrilB1531/lodestar/issues/765).

Reading: [decision 0132](https://github.com/CyrilB1531/lodestar/blob/53af23c2/docs/decisions/0132-preprocessing-writes-splitters-scalers-and-encoders-and-not-smote.md),
which keeps both out of the first scalers lot and records them here; and
[decision 0138](https://github.com/CyrilB1531/lodestar/blob/53af23c2/docs/decisions/0138-lodestar-preprocessing-takes-an-edge-on-lodestar-stats-for-the-normal-quantile.md),
which took this package's first inter-package edge and set the precedent the sparse half needs.
`sklearn.preprocessing` 1.9.0 read by probe.

## Problem

Two things `docs/equivalence.md` has scoped out since `Lodestar.Preprocessing` 0.1.0:

- **A scaler fitted over batches.** `Fit` sees the whole matrix, so a caller whose data does not fit
  in memory — or arrives over time — has nothing to call.
- **A scaler over sparse input.** `CsrMatrix` is the sparse primitive this repository already
  publishes ([decision 0071](https://github.com/CyrilB1531/lodestar/blob/53af23c2/docs/decisions/0071-csrmatrix-moves-to-an-abstractions-package.md)), and
  the scalers cannot take one.

## What the reference does, measured

1. **`partial_fit` chained agrees with `fit` on the concatenation to a couple of units in the last
   place — not bit for bit.** Measured over two, three and four batches: the worst relative gap on
   the reference's *own* two paths is **3.3e-16**, and one case of three batches differs in the last
   bits of the variance and the scale. The update is
   `sklearn.utils.extmath._incremental_mean_and_var`, Chan, Golub and LeVeque's parallel form; the
   correction term is what keeps the gap at that size rather than at the square of it.
2. **`n_samples_seen_` changes type.** It is a scalar with no `NaN` in the data and a **per-feature
   array** when there is one, because a feature whose value was missing saw one sample fewer.
3. **`RobustScaler` has no `partial_fit`.** A median is not updatable from a summary, and the
   reference does not pretend otherwise — `hasattr(RobustScaler(), "partial_fit")` is `False`.
4. **Sparse is accepted by three and refused by three, each with its own message:**
   `StandardScaler(with_mean=False)`, `MaxAbsScaler` and `RobustScaler(with_centering=False)` accept
   a CSR matrix; `StandardScaler()` and `RobustScaler()` raise *"Cannot center sparse matrices"*;
   and **`MinMaxScaler` refuses sparse outright**, pointing at `MaxAbsScaler` instead.

## Placement

```csharp
public sealed class StandardScaler
{
    public StandardScaler PartialFit(ReadOnlySpan<double> samples);
    public static StandardScaler Fit(CsrMatrix samples, StandardScalerOptions options = null);
}
```

- **`PartialFit` returns a new scaler; it does not mutate.** Every fitted object in this package is
  immutable, and the reference's own `partial_fit` returns `self` so that
  `scaler = scaler.PartialFit(batch)` reads the same on both sides. A mutable scaler would also be a
  scaler whose `Transform` changes answer under a concurrent reader, which nothing here does today.
- **`SampleCount` stays one `int`.** The reference's per-feature count exists to track missing
  values, and these scalers refuse a non-finite value (#763) — so the counts cannot diverge, and the
  divergence is a consequence of a policy already recorded rather than a simplification of this lot.
- **`PartialFit` on three scalers, not four**: `StandardScaler`, `MinMaxScaler` and `MaxAbsScaler`.
  `RobustScaler` does not get one, for the reference's own reason.
- **`Fit(CsrMatrix)` on three, refusing on the ones the reference refuses**, each with the message
  that names the alternative — `MinMaxScaler` has no sparse overload at all, which is a compile-time
  refusal rather than a run-time one and is the better spelling of the same rule.
- **Rejected:** a mutable `PartialFit(void)`. It matches the reference's spelling and breaks the
  package's one invariant.
- **Rejected:** a `partial_fit` that takes `CsrMatrix`. The reference has it; nothing here has a
  caller for the combination, and each half is already its own risk (decision 0095's rule).

## The second edge

`CsrMatrix` lives in `Lodestar.Abstractions`, so the sparse half takes
**`Lodestar.Preprocessing` → `Lodestar.Abstractions`**, this package's second inter-package edge and
the fifteenth to become the sixteenth. Decision 0138 settled the principle — *a member another
`Lodestar` package publishes is depended on, not copied* — so this follows it rather than reopening
it, and needs its own record because the graph is asserted rather than reviewed:

- an ADR, applying 0138 and 0071;
- `tools/check_nuspec_dependencies.py`'s `EXPECTED`;
- `CLAUDE.md`'s table and edge count;
- the `.csproj` pair, `PackageReference` on the published floor with the `LodestarUseProjectRefs` opt-in;
- **the netstandard mirror's own `ProjectReference`** — `SetTargetFramework` does not cross a
  `PackageReference`, which `check_netstandard_guards` caught on the first edge.

`Lodestar.Abstractions`' floor is **0.1.1**, published, and `Lodestar.Text` and `Lodestar.Decomposition`
already pull it.

## Evidence

- **`preprocessing_partial_fit.json`** from `sklearn.preprocessing`: each of the three scalers fitted
  over two and three batches of uneven size, against the same data fitted whole; single-row batches;
  and a batch that widens a `MinMaxScaler`'s range beside one that does not. **Both answers are
  frozen in every case**, because the claim is not that the incremental statistics are right on
  their own but that they are the ones a single fit gives — to 1e-9, which is six orders wider than
  the 3.3e-16 the reference's own two paths differ by. The batches are uneven on purpose: equal ones
  would let an implementation that averages two batch means pass.
- **`preprocessing_sparse.json`**: the three scalers that accept sparse, over a matrix with an
  all-zero column and a column with one stored value, against the dense answer for the same data.
- **Edge tests:** the refusals the reference makes, each with its own message; `PartialFit` on a
  shape that does not match the first batch; and `RobustScaler` having no `PartialFit` at all, which
  is asserted by the reference gate rather than by a test.
- **Benchmark:** `PartialFitBenchmarks` — chained batches against one whole `Fit`, which is the cost
  a caller pays for not holding the matrix; and the sparse path against the dense one on the same
  data, where the saving is the zeros not visited.
