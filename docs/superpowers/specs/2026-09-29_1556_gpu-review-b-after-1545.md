## The problem

The Review B of `Lodestar.Gpu` after #1545, on `main` at `54e85920`, found four defects:

- Three links still sent readers to `docs/guides/performance.md` for the kernel figures, which is
  now an index; the figures live in `src/Lodestar.Gpu/performance.md`.
- The README the package ships left bit-parallel edit distance out of its summary.
- `Signatures` and `Multiply` sized their output in `long` on the device but copied it into one
  host array only after the kernel ran, so a result past one array paid the whole launch and then
  failed with an exception no page listed.
- Two branches #1545 added were untested: `DeviceTextBlock`'s character-count refusal, which no
  string can reach cheaply, and the OpenCL GPU-bit test, which CI never reaches.

## Decisions

- **Refused before the launch.** `Signatures` refuses `documents × permutations` past one array
  under `multipliers`; the resident `Multiply` refuses `rows × width` under `block`, which covers
  the host overload too. A resident block past one array is refused rather than kept: `Upload`
  already bounds a block to one array, and `Download` could never return a larger one.
- **The checks moved where a test reaches them.** The character sum is `CharacterTotal`, over
  lengths rather than strings, and the OpenCL bit test is `HasGpuBit`, over a `CLDeviceType`.
