# A save writes any length and a load reads it back, the idf block is refused first, and the Aalen predictions document their table

**Issues:** [#1616](https://github.com/CyrilB1531/lodestar/issues/1616),
[#1617](https://github.com/CyrilB1531/lodestar/issues/1617),
[#1618](https://github.com/CyrilB1531/lodestar/issues/1618).
**Status:** written with the work, 2026-10-01.
**Date:** 2026-10-01.

## The problem

The Review B after #1615, on `main` at `9d4007eb`, found one `int` product #1614 had not bounded:
`Base64Numbers.WriteDoubles`, which a `TfidfVectorizer` save writes its idf weights through, sized
its byte buffer as `values.Count * sizeof(double)`, wrapping negative from 268,435,456 weights.
Review A of the fix found the real limit lower: `Utf8JsonWriter` refuses to grow its buffer past
`int.MaxValue` less a mebibyte, so the save failed with an undocumented `OutOfMemoryException` from
about 201,228,000 weights with nothing else in the artifact — after the header, the options and the
vocabulary were written, a file `Save(string)` had already truncated. It also found four `AalenSummary` predictions —
survival function, percentile, median, expectation — documenting only the design among their
refusals, though each goes through `PredictCumulativeHazard`, which refuses rows times event times
past one array, reachable at 100,000 subjects against 30,000 event times.

The same Review A found the artifact around the block unbounded (#1618): `Utf8JsonWriter` writes to
its stream only when flushed — measured, 1.3 MB of strings pending and none on the stream — so a
`CountVectorizer` or `TfidfVectorizer` save held its whole artifact in the writer and failed past
about 2 GB, `SaveAsync` composed it in a `MemoryStream` with the same ceiling, an `EmbeddingIndex`
save held every id until the block, and the loads read into one array, `EmbeddingIndex` alone
segmenting a seekable stream past it (#377). A string the writer refuses — past 166,666,666
characters, a raw value past 715,827,882, which a lone surrogate is written as, and fewer
characters where escaping multiplies them: 130,000,000 of U+0001 failed — failed partway through a save.

## Decisions

- **The bound is the writer's buffer, with two mebibytes to spare.** `Base64Numbers.WritableAsProperty`
  asks whether the base64 text fits `int.MaxValue` less two mebibytes: refused from 201,129,984
  weights. Measured on System.Text.Json 10 with the writer flushed before the block, as it now is,
  201,326,561 weights write and 201,326,562 fail with `OutOfMemoryException`; the first measurement,
  with the artifact still pending ahead of the block, put the ceiling a mebibyte lower, and the
  margin stands for the writer builds not measured, .NET Framework's among them. `EmbeddingIndex`,
  whose block is written in slices past the writer, computes its length with the same `EncodedLength`.
- **Refused before the first byte, where `main` met it.** Every save checks the weights, finiteness
  first and then the block's length, before its first byte: once the writer has accepted the stream,
  which refused a read-only one first, and once `Save(string)` has opened the file, which refused a
  bad path first, as `main`'s write met them; at the start of `SaveAsync`, which became `async` so its
  refusals, the null stream first, still surface through the task. Checking before opening was tried
  and dropped: it left a good file whole, but a path's refusal then needed a probe, and every probe
  — opening without truncating, creating new and deleting on close — parted from `FileMode.Create` on
  some file a directory, a symlink, a hidden file or a race made. A refused save leaves the file
  empty, where `main` left it half written. A non-finite weight keeps its `InvalidDataException`, now
  before the header rather than after the vocabulary, and is documented; the write checks it again,
  so weights changed since never reach the file.
- **`InvalidOperationException`**, as `EmbeddingIndex` refuses an index no load can read: the fitted
  state is what no artifact holds, and no argument names it.
- **The raw buffers allocate `checked`.** `WriteDoubles` is reached only behind the bound; nothing
  in production calls `WriteSingles`, so its big-endian buffer is only made to fail loudly too.
- **A save writes any length, and a load reads whatever a save wrote (#1618).** Bounding the
  artifact's total before the first byte was rejected: an exact size needs every term's escaped
  UTF-8 length, and the refusal would only move the ceiling a load imposed onto the save. Instead
  every list a save writes — vocabulary, stop words, ids — flushes the writer once a mebibyte is
  pending, the idf block having the buffer to itself; `SaveAsync` and the index's asynchronous head
  compose in a `SpillBuffer` of chunks doubling from 256 bytes to a mebibyte, rather than a
  `MemoryStream`; and every load of an
  artifact a save writes reads past one array as a segment sequence, from a seekable stream in
  64 MiB segments and from one of undeclared length in segments doubling from 80 KB to a mebibyte, filled from 80 KB reads counted as before,
  joined into one array while they fit one. The parsers were already sequence-ready, #377 having
  made them so for the index. Flushing writes the caller's stream partway through a save, so every
  refusal a save makes runs before its first byte: a vocabulary term, a stop word, the token
  pattern or an id the writer refuses is refused there — a string past ten million characters is
  written once into nothing to find out, since the ceiling depends on its escaped UTF-8 — with
  `InvalidOperationException` as the block is. `HashingVectorizer`, whose stop words go through the
  same writer, checks and reads the same way. Those checks run where `main`'s write met the strings:
  after the path is opened and the writer has accepted the stream — an asynchronous save, whose head
  composes in memory, still makes that writer for its refusal. A null stop word is left to the write,
  where `main` met it.
- **The four predictions name the table their call builds**, and every Aalen prediction now says the
  design is bounded with any intercept column, as the code sizes it; the code was already right.
